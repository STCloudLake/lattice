# M2a — 推送层：捕获是兴趣信号，知识像广告一样投放

> 本节把产品方向写死，避免以后又滑回"把页面变成卷子"。
> 来源：`E:\Computhon\One_Page_Further_Work.md`、`Pitch_Script_Bilingual.md` 里"像投放广告一样投放知识"的原始设计。

---

## 1. 一句话

**捕获一个页面 ≠ 给这个页面出题；捕获一个页面 = 告诉系统"我对这个领域感兴趣"。**
系统负责把该领域的内容拆成有先修结构的命题，然后按剂量、按顺序、以广告的形式推给用户；
验证（quiz/评级）是可选项，默认不要求。

## 2. 为什么不是"捕获什么就复习什么"

如果每捕获一页就把所有句子变成待复习卡片，会产生三个问题：

1. **用户得到的是卷子，不是路径**——今天抓十页，明天欠五十张卡，产品变成负罪感来源。
2. **没有系统性**——页面是碎片，先修关系不在页面里；不做图，就永远是随机事实。
3. **没有取舍**——用户对某个领域感兴趣，不代表他要背下这一页的每一句。

所以 M2a 把"捕获"的语义改成**兴趣证据**，把"复习"降级为可选动作，把"推送"升级为主入口。

## 3. 四本账里它落在哪

| 账本 | M2a 里的内容 | 谁写 |
|---|---|---|
| **K 知识** | 命题、推理链、领域（`proposition.domain`） | 抽取管线 |
| **M 掌握** | Beta 后验，只被作答/解释改变 | 复核、测验 |
| **S 调度** | FSRS，只被评级改变 | 复习 |
| **C 上下文** | **兴趣**（`interest.observed`：领域权重、捕获次数）与**曝光**（`exposure.*`：展示/参与/跳过） | 捕获、推送 |

**硬规则**：曝光只进 C 账，永不改 M/S。看了一整天不等于学会了。

## 4. 推送策略（`packages/core/src/feed.ts`）

输入：事件日志重放后的状态 + 当天日期 + 剂量。
输出：`FeedItem[]`（≤ dose），每项带 `reason` 与 `domain`。

规则按顺序：

1. 同一命题**一天只出现一次**（`exposure.lastShownDay` 去重）——广告逻辑里的"频次控制"。
2. 用户**跳过两次**就不再推（`skipped >= 2`）——"不感兴趣"要被尊重。
3. **到期复习最多占剂量的 40%**（`reviewShare`）——避免复习债务挤掉新内容。
4. 其余是**前沿新内容**：所有（传递）先修的掌握度 ≥ 0.7 才推；没有先修的是"基础命题"。
5. **兴趣权重只影响排序，不影响掌握度**：`domain` 命中的兴趣权重越高，越靠前。

排序：复习 `(1-R)·2.2·boost`，新内容 `(0.6·(1-mastery) + 0.4·链条中心性 + 基础加成)·boost`。
同一状态下输出完全确定（可复现、可测试）。

## 5. 表面（本轮做新标签页，侧栏/通知留到后面）

- 新标签页 = **今日推送**：一次一张，领域徽标 + 类型标签 + 命题 + 一句提示；
- 动作：**知道了**（参与）/ **不感兴趣**（跳过）/ **考考我**（进入复核，可选）；
- 空状态 = "今天的知识看完了"，并引导去复习或再捕获一个页面；
- 复习队列仍然存在，但从"主界面"降级为"可选入口"。

## 6. 与原设计的对应

| 原设计 | M2a |
|---|---|
| 像投放广告一样投放知识 | 每日剂量 + 频次控制 + 被动曝光 |
| 被动曝光会积累 | 曝光进 C 账，作为兴趣与时机证据；不伪造掌握 |
| 验证模式默认关闭 | 复核/测验变成"考考我"按钮 |
| Agentic 自适应投放 | 先做**可复现的策略函数**（前沿 + 到期 + 兴趣），Agent 只负责解释与生成 |
| 行为追踪 | `exposure.shown/engaged/skipped` 事件 |
| 侧栏 2-3 条、30 秒收起 | 下一轮（M2b）：inject 侧栏，读同一份 feed |

## 7. 指标（下一步要能测）

- **被动曝光率**：今日 dose 中实际渲染的比例；
- **微交互率**：知道了 / 考考我 的比例；
- **领域覆盖率**：某领域链上命题被推送过的比例；
- **7/30 天留存**：仍在打开新标签页并消费 feed 的比例。

## 8. 明确不做

- 不把捕获内容强制转成待复习卡；
- 不在推送里塞 quiz（要用户主动点"考考我"）；
- 不用曝光提升掌握度；
- 不在 M2a 做通知/侧栏（M2b）。

## 9. 声明兴趣与自主补课（M2c）

推送不能只依赖"你捕获了什么"。两个补充机制：

1. **声明兴趣**（`interest.declared`）：用户在设置里直接选领域与水平（入门/进阶/高级）。
   声明兴趣的排序权重高于捕获推断（×1.4），`interest.removed` 可撤回声明但保留捕获证据。
2. **自主补课**（`generateCurriculum`）：当声明领域的内容不足或今日推送为空时，系统按
   `curriculumLevelFor()` 决定阶段（初学→入门，领域平均掌握 ≥0.55→进阶，≥0.8→高级），
   让模型生成下一小批「先修有序」的命题与推理链，写入图谱后进入正常推送。
   约束：每领域每天最多一次，进行中不重复触发，没有配置模型时只提示不生成。
3. **种子课程**：`examples/seed-curriculum.json` 随扩展打包（计算机 / 人工智能，入门），
   首次启动自动导入并声明这两个兴趣——保证没配模型、没捕获时也能看到系统在推送。

水平的作用是**生成阶段的起点**，不是给用户贴标签：它只决定"下一批内容多深"，掌握度提高后自动升级。

## 10. 两个 correctness 修正（M2c+）

1. **领域实体归并**（`packages/core/src/domains.ts`）：同一领域的不同叫法
   （`CS` / `Computer Science` / `计算机`、`AI` / `人工智能`）通过内置别名表 +
   `domain.alias` 事件解析到同一个规范名；归并在 replay 后统一执行，所以"先捕获、
   后声明别名"也能合并。子领域（机器学习 vs 人工智能）**不合并**——那会改变语义。
2. **兴趣时间衰减**：兴趣权重在读取时按半衰期衰减（捕获推断 60 天，声明兴趣 240 天）。
   三个月前抓的领域不会和昨天声明的一样重；原始权重仍然保留在事件里（可审计、可重放）。
3. 两者都只影响**排序与计数**，不影响掌握度与调度；`lattice domains` 命令可查看
   规范名、别名、衰减前后权重与命题数。

## 11. 环境表面（M2c）

推送不再只发生在新标签页和视频侧栏，而是"任意页面上的广告位"：

| 表面 | 出现方式 | 不打扰的约束 |
|---|---|---|
| **环境胶囊**（任意 http(s) 页面） | 右下角 44px 胶囊，点开成 300px 面板 | `position:fixed`，不改变页面布局；窄屏只显示胶囊 |
| **视频侧栏**（bilibili/YouTube） | 右侧窄栏，最多 2 条 | 不覆盖播放器；30 秒自动收起 |
| **评论区/推荐位** | 原生排版的卡片 | **始终带 `Lattice` 标识**；每页最多各 1 条 |
| **系统通知** | 每天最多 1 条，默认关闭 | 与侧栏共享打断预算 |

**随机出现**：视频站约 50%、其它页面约 25%，同一标签页 20 分钟冷却，每日预算内最多 1 个环境表面。
**敏感站点**（邮箱、银行、支付、本地管理页）硬排除；每个站点可"此站不再显示"。

**点击"感兴趣" → 站内搜索跳转**：B 站跳 `search.bilibili.com/all?keyword=…`，
YouTube 跳 `/results?search_query=…`；非视频站打开 Lattice 新标签页。跳转按 `exposure.engaged` 记账。

**不做的事**：不伪造用户评论（无假用户名/头像/点赞/时间），见 `ETHICS.md`。
原生感来自排版与位置，不来自冒充。

## 12. 开放问题

1. 剂量应该按"条"还是按"阅读时长"控制？
2. 兴趣权重是否需要时间衰减（三个月前抓的领域还算兴趣吗）？
3. 领域是 LLM 抽的，跨材料可能不一致（"经济学"/"微观经济学"）——需要实体归并。
