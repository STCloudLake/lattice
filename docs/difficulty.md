# 知识难度分级

> 目标：让推送知道"这个知识点有多难、要求什么认知操作"，从而按学习者的阶段
> 选择内容；而不是把所有事实当成一样难。
>
> 参考：`E:\QA\大模型课程-2026` 用 **★1–5 章节难度 + 前置 + 预计时长**，以及
> **L1–L4 能力层级（实现/复现/训练/改进/表达）**。本设计把它下沉到**单个命题**。

## 1. 为什么两个维度

一个事实的"难"至少有两种：

- **获取难度**（`tier` 1–5）：没有先修时，把它弄懂有多难。
- **认知操作**（`cognitive`）：要证明"你会了"，你需要做什么——记住、解释、套用、推导、评判。

两者独立：`哈希表平均查找 O(1)` 获取难度低（★1–2），但要求 `apply`（你得会选择
并使用它）；`从预算约束推导需求曲线` 获取难（★4），认知是 `analyze`。

只用一个分数会导致两种错误：把"能背"当成"会推导"；把"术语"当成"简单"。

## 2. 判定规则

| 规则 | 说明 |
|---|---|
| 只评知识点，不评人 | 同一个命题对不同人难度不同，那是 mastery 的事 |
| 边际难度 | `tier` 是**先修已具备时**的难度；结论可以比前提低 |
| 不按长度 | 长段落不等于难，短公式可以是 ★4 |
| 认知取最低充分操作 | 能"背"就算会 → 不要标 `evaluate` |
| 分布要合理 | 一批入门内容全 ★3 说明没在认真评 |

## 3. 数据结构

```ts
interface Difficulty {
  tier: 1 | 2 | 3 | 4 | 5;
  cognitive: 'remember' | 'understand' | 'apply' | 'analyze' | 'evaluate';
  minutes?: number; // 首次理解，不复述掌握
}
```

写入 `proposition.asserted` 的 payload：

```json
{"statement":"…","domain":"经济学","difficulty":{"tier":3,"cognitive":"apply","minutes":10}}
```

## 4. 三个入口

1. **捕获抽取**（`extract-v2`）：模型给每条命题附 `difficulty`，校验非法值降级为警告。
2. **课程生成**（`curriculum-v2`）：按声明的水平给 tier 范围（入门 1–2 / 进阶 3 / 高级 4–5）。
3. **补标已有内容**（"委托给 API"）：`gradeDifficulty(items, {llm})`，版本 `grading-v1`，
   返回 `{grades, dropped}`，可直接回填事件日志。

Skill 版本（给任意 agent 用）：[`skills/difficulty-grading/SKILL.md`](../skills/difficulty-grading/SKILL.md)。

## 5. 推送如何使用

`buildFeed()` 里：

- 每个命题的**目标 tier** 来自它所属领域的声明水平：入门→2、进阶→3、高级→4。
- **硬过滤**：`tier > 目标 + 2` 的命题不推（看不懂的广告就是噪音）。
- **软排序**：`levelFit = 1 - |tier - 目标|/4`，占分数的 12%。
- `FeedItem` 带出 `tier` / `cognitive`，界面显示 `★★★☆☆` 与中文标签。

难度只影响**排序与过滤**；掌握度、调度、兴趣都不因此改变。

## 6. 与 L1–L4 能力模型的关系

那套课程的 L1–L4 是**学习者阶段**（能实现/能复现/能训练/能改进/能表达）；
本设计评的是**知识点**。两者通过"目标 tier"关联：声称要往 L4 走时，系统把目标
tier 提到 4–5，并优先推 `analyze/evaluate` 的命题。学习者阶段仍然由掌握度和行为决定，
不由自评决定。

## 7. 开放问题

1. **分级校准**：目前没有 ground truth；需要人工抽检 50 条，比较模型分级与人工分级的一致率。
2. **难度与先修深度的耦合**：是否应该用图深度修正 `tier`？暂不做，避免循环定义。
3. **界面编辑**：用户还不能手动改某条命题的难度（事件可写，缺 UI）。
4. **多语言/多领域分布偏移**：中文教材与英文论文的难度锚点可能不同。
